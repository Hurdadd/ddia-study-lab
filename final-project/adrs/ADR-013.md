# ADR-013 — زبان و framework را از کجا انتخاب کنیم؟

How do we choose languages and frameworks?

Status: proposed · Date: 2026-10-15

## مسئله / Context

پیش‌نویس Java/Python رو نام برده، ولی مهارت تیم، زمان و قرارداد adapter هنوز بررسی نشدن.

The draft names Java/Python, but team skills, the schedule, and the adapter contracts still haven't been looked at.

## گزینه‌ها / Alternatives

Python-only؛ Java-only؛ Java API با Python adapter.

Python-only, Java-only, or Java API with Python adapters.

## انتخاب فعلی / Choice

انتخابِ پلتفرم هنوز باز است؛ یک slice کوچک را با گزینه‌های قابل‌نگهداری مقایسه می‌کنیم. Java در مثال‌های درس سابقه دارد، نه الزامِ پلتفرم.

The platform implementation choice is open: compare a small slice using maintainable options. The existing Java teaching examples don't mandate the platform language.

## چرایی و trade-off / Rationale and trade-off

یک زبان راه‌اندازی را ساده‌تر می‌کند؛ دو زبان دسترسی به ecosystem را بهتر می‌کند ولی deployment و debuggingِ قراردادها را پیچیده‌تر.

One language gets you started faster; two give you better ecosystem access but make the deployment and the contract debugging harder.

## فرض‌ها / Assumptions

مهارت تیم، محدودیت host و هزینهٔ نگهداری هنوز ورودی ما نیستن.

Team skills, host constraints, and maintenance costs still aren't in the picture.

## روش آزمون / Validation

یه endpoint و worker با همون contract؛ زمان توسعه، integration test، پکیج و trace رو مقایسه کن.

One endpoint and one worker under the same contract; compare the development time, the integration test, the packaging, and the trace.

## بازنگری / Revisit

وقتی نیازِ library یا ظرفیت واقعی انتخاب فعلی را محدود کرد، ADR تازه ثبت می‌کنیم. اول نیاز، بعد زبان.

Revisit with a new ADR when required libraries or measured capacity constrain the current choice. The need first, the language second.
