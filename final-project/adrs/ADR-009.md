# ADR-009 — چرا مجوز را به مدل واگذار نکنیم؟

Why is authorization outside the model?

Status: proposed · Date: 2026-10-15

## مسئله / Context

prompt و سند می‌تونن اشتباه یا آلوده باشن؛ tenant و policy باید مستقل enforce بشن.

Prompts and documents can be wrong or malicious; tenant and policy have to be enforced independently.

## گزینه‌ها / Alternatives

محدودیت در prompt؛ filter روی index؛ policy gate همراه با guard مرجع.

Prompt restrictions, index filters, or a policy gate backed by authoritative guards.

## انتخاب فعلی / Choice

tenant از هویت؛ policy در tool gateway و guard در query/output؛ و ACL فعلی، حتی برای cache و citation قدیمی.

The tenant comes from the identity, the policy lives in the tool gateway, the guard sits in query/output, and the current ACL applies even to caches and old citations.

## چرایی و trade-off / Rationale and trade-off

متنِ خروجی مدل authority نیست؛ revocation در run جاری باید انتشار خروجیِ مبتنی بر context قدیمی را متوقف یا دوباره تولید کند.

The model's text is not authority. A revocation mid-run has to stop the publication of anything built on the revoked context, or regenerate it.

## فرض‌ها / Assumptions

نحوهٔ auth واقعی و data classification هنوز باید تعریف بشه؛ سناریوهای آزمون هم مصنوعی‌ان.

The real auth scheme and the data classification still need defining; the test scenarios are synthetic.

## روش آزمون / Validation

prompt injection، cross-tenant ID، revoked context در حال پرواز، و backup replay.

Prompt injection, a cross-tenant ID, revoked context in flight, and a backup replay.

## بازنگری / Revisit

هر ابزار تازه یا دادهٔ حساس تازه، threat model و همین ADR را بازبینی می‌کنه. دادهٔ حساس، قاعدهٔ تازه می‌خواهد.

New tools or sensitive data require reviewing this ADR and threat model. Sensitive data earns a fresh rule.
