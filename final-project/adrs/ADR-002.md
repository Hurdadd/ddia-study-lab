# ADR-002 — نسخهٔ اول دقیقاً چه کاری انجام می‌دهد؟

What does the first version actually do?

Status: proposed · Date: 2026-10-15

## مسئله / Context

ساختِ هم‌زمانِ همهٔ قابلیت‌ها، گرفتن بازخورد و فهم خرابی‌ها را سخت می‌کند.

Building every capability at once makes feedback and failure diagnosis harder.

## گزینه‌ها / Alternatives

همهٔ پنج قابلیت به‌صورت کامل؛ یا یک مسیر end-to-end کوچک و قابل‌آزمایش.

Five complete capabilities at once, or one small testable end-to-end path.

## انتخاب فعلی / Choice

ثبت برنامه → ارسال run → یک call مدل و یک ابزار خواندنی → نتیجه و trace؛ بعدش توسعهٔ مرحله‌ای.

Register the app → submit a run → one model call and one read-only tool → result and trace; then we expand.

## چرایی و trade-off / Rationale and trade-off

اول قرارداد مشترک پلتفرم را اثبات می‌کنیم؛ phase اول به GPU، Kafka و Kubernetes وابسته نیست.

We prove the reusable platform contract first; the first phase doesn't depend on GPUs, Kafka, or Kubernetes.

## فرض‌ها / Assumptions

E01 حجم پایلوت و E02 سقف callها فرض‌اند. دادهٔ پایلوت واقعی هنوز نداریم.

Pilot volume E01 and call count E02 are assumptions; real pilot data doesn't exist yet.

## روش آزمون / Validation

developer یک app ساده و یک app ابزارمحور را از همان قرارداد اجرا می‌کند؛ پاسخ گم‌شده run جدید نسازد.

Run simple and tool-using apps through the same contract; lost responses don't create duplicate runs.

## بازنگری / Revisit

وقتی مسیر اول اثبات شد، قابلیت‌های context، eval و serving با gate مستقل اضافه می‌شوند. یکی‌یکی، نه یه‌جا.

Once the first path works, we add context, evaluation, and serving behind separate gates. One at a time, not all at once.
