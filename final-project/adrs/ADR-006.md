# ADR-006 — چه زمانی CDC و Kafka لازم می‌شوند؟

When are CDC and Kafka justified?

Status: proposed · Date: 2026-10-15

## مسئله / Context

تازه‌ماندن context و چند consumer مستقل، در مراحل بعد لازم می‌شوند؛ برای اولین call مدل اصلاً الزامی نیستند.

Fresh context and independent consumers matter later; for the first model call they aren't needed at all.

## گزینه‌ها / Alternatives

polling با cursor؛ outbox polling؛ log CDC و Kafka.

Cursor polling, outbox polling, or log CDC with Kafka.

## انتخاب فعلی / Choice

فاز context: برای منبع تحت مالکیت، business+outbox اتمی و بعد CDC؛ Kafka وقتی replay/fan-out مستقل ارزشش را نشان بدهد.

Context phase: for a source we own, an atomic business/outbox change and then CDC; Kafka once independent replay/fan-out earns its keep.

## چرایی و trade-off / Rationale and trade-off

dual write می‌تواند شکاف یا ترتیب متفاوت بسازد؛ اضافه‌کردن broker بدون نیاز هم هزینهٔ نگهداری دارد.

A dual write can leave a gap or a different order; adding a broker you don't need still costs you operations.

## فرض‌ها / Assumptions

E07 پنج event/ثانیه و دو KB/event؛ E08 هفت روز replay؛ همه‌شان فرض‌اند.

E07 assumes five events/second and 2KB/event; E08 assumes seven days of replay. All assumptions.

## روش آزمون / Validation

snapshot هم‌مرز، overlap/delete/replay و cursor expiry؛ بعد مقایسهٔ freshness/هزینه با polling ساده.

Boundary-aligned snapshots, overlap/deletion/replay and cursor expiry; then compare freshness and cost against plain polling.

## بازنگری / Revisit

اگر polling نیازِ تازگی را با هزینهٔ کمتر جواب داد، CDC/Kafka را می‌بریم مرحلهٔ بعد. زودتر از نیاز، هزینه‌ست.

If polling meets freshness needs more cheaply, we push CDC/Kafka to the next stage. Earlier than you need is just cost.
