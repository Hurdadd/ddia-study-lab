۱1انتخاب‌ها و هزینه‌های معماری سیستم‌های دادهTrade-offs in data systems architecture

  • backup and restoreپشتیبان‌گیری و بازیابیکپی گرفتن از داده و بعد برگرداندنش سر جایش، وقتی که لازم شد.Copying the data somewhere else, and putting it back when you need it.
  • change data captureثبت تغییر دادهخواندن لاگ تغییرات دیتابیس و پخش‌کردن هر تغییر به‌عنوان یک رویداد مرتب.Reading the database change log and publishing each change as an ordered event.
  • crypto-shreddingپاک‌سازی با کلیدپاک‌کردن داده با دور انداختن کلیدش، نه با گشتن دنبال هر نسخه.Erasing data by discarding its key instead of hunting down every copy.
  • data lakeدریاچهٔ دادهانبار بزرگی از دادهٔ خام که ساختارش را فقط وقت خواندن تعیین می‌کنی.A large store of raw data whose structure is decided only when you read it.
  • data warehouseانبار دادهکپی خواندنی و جدا از سیستم عملیاتی که دادهٔ چند سیستم را برای تحلیل جمع می‌کند.A separate read-only copy that gathers data from many operational systems for analysis.
  • data-intensiveداده‌محورسیستمی که محدودیت اصلی‌اش حجم و پیچیدگی داده است، نه توان پردازش.A system whose real limit is the volume and complexity of data, not raw compute.
  • derived dataدادهٔ مشتقداده‌ای که از دادهٔ دیگر ساخته می‌شود و در اصل از نو ساختنی است.Data built from other data, which in principle can be rebuilt from its source.
  • dual writeنوشتن دوگانهنوشتن یک تغییر در دو سیستم از یک مسیر کد، بی‌آنکه هر دو با هم انجام شوند.Writing one change into two systems from one code path, with no promise both happen.
  • ETLاستخراج، تبدیل، بارگذاریکشیدن داده از سیستم‌های مبدأ، یکدست کردنش، و ریختنش در انبار داده.Pulling data from sources, making it consistent, and loading it into the warehouse.
  • HTAPپردازش ترکیبییک موتور که هم تراکنش‌های روزمره و هم تحلیل‌های سنگین را جواب می‌دهد، بدون کپی جدا.One engine serving both everyday transactions and heavy analytics, without a separate copy.
  • multitenancyچندمستأجریسرو کردن چند مشتری از یک زیرساخت مشترک، با مرزی که هر کس را در جای خودش نگه دارد.Serving many customers from one shared infrastructure, with a boundary that keeps each in place.
  • OLAPپردازش تحلیلیپرس‌وجوهایی که میلیون‌ها ردیف را می‌خوانند و به یک عدد یا جدول کوچک می‌رسند.Queries that read millions of rows and return a single number or a small table.
  • OLTPپردازش تراکنشیخواندن و نوشتن تعداد کمی رکورد در هر درخواست، با تأخیر کم و درستی قطعی.Reading and writing a handful of records per request, with low latency and firm correctness.
  • outboxصندوق خروجینوشتن رویداد در همان تراکنش دیتابیس، تا فرستادنش بعداً و مطمئن انجام شود.Writing the event inside the same database transaction, so sending it happens later and safely.
  • PIIدادهٔ شناسایی‌پذیر شخصیداده‌ای که با آن می‌شود یک نفر مشخص را پیدا کرد، تنها یا کنار چند دادهٔ دیگر.Data that can point to one specific person, alone or beside a few other facts.
  • reverse ETLETL معکوسبرگرداندن نتیجهٔ تحلیل از انبار داده به ابزاری که کار روزمره در آن انجام می‌شود.Sending an analysis result back from the warehouse to the tool where daily work happens.
  • RPO / RTOهدف نقطه و زمان بازیابیدو عدد که می‌گویند چقدر داده را می‌توانی از دست بدهی و چقدر می‌توانی بی‌جواب بمانی.Two numbers: how much data you may lose, and how long you may stay unavailable.
  • serverlessبی‌سروراجرای کد روی ماشین کسی دیگر، به‌ازای هر درخواست، بدون اینکه سروری را خودت نگه داری.Running your code on someone else's machines, per request, without keeping a server.
  • system of recordمنبع حقیقتجایی که نسخهٔ رسمی و معتبر یک داده نگه داشته می‌شود.The place that keeps the official, authoritative version of a piece of data.
  • tombstoneسنگ‌قبرنشانه‌ای که جای رکورد حذف‌شده نوشته می‌شود و تا فشرده‌سازی می‌ماند.A marker written in place of a deleted record, which stays until compaction runs.

۲2تعریف نیازمندی‌های غیرعملکردیDefining nonfunctional requirements

  • availabilityدسترس‌پذیریسهم زمانی که سیستم واقعاً می‌تواند جواب بدهد، از دید کسی که از آن استفاده می‌کند.The share of time a system can actually answer, measured from where its users stand.
  • availability zoneمنطقهٔ دسترس‌پذیریبخشی از یک منطقه که برق، خنک‌کننده و شبکهٔ جدا دارد تا خرابی‌اش به بقیه سرایت نکند.A slice of a region with its own power, cooling and network, so its failure does not spread.
  • cacheکشنگه داشتن جوابِ کارِ گران، نزدیک‌تر به کسی که دوباره می‌خواهدش.Keeping the result of expensive work closer to whoever will ask for it again.
  • chaos engineeringمهندسی آشوبخرابی عمدی و کنترل‌شده در سیستم، تا بفهمی واقعاً چه اتفاقی می‌افتد نه اینکه چه فکر می‌کنی.Deliberately breaking the system in a controlled way, to learn what really happens rather than what you assume.
  • control planeلایهٔ کنترلبخشی از سیستم که تصمیم می‌گیرد کار کجا و چطور انجام شود، نه بخشی که انجامش می‌دهد.The part of a system that decides where work should run, not the part that runs it.
  • data planeلایهٔ دادههمان مسیری که درخواست‌ها و داده‌ها از آن رد می‌شوند، در برابر مسیری که تنظیمات را عوض می‌کند.The path requests and data actually travel, as opposed to the path that changes configuration.
  • error budgetبودجهٔ خطاسهم مجاز خطا از یک هدف؛ وقتی تمام شود، کار تازه می‌ایستد و تعمیر شروع می‌شود.The share of failure a target allows; when it runs out, new work stops and repair starts.
  • evolvabilityتحول‌پذیریتوانِ عوض کردن سیستم بدون شکستن چیزهایی که امروز کار می‌کنند.The ability to change a system without breaking what already works.
  • failoverجابه‌جایی به جانشینبردن کار روی یک نسخهٔ دیگر، وقتی نسخه‌ای که مسئول بود از دسترس خارج می‌شود.Moving the work to another copy when the one in charge goes out of reach.
  • failure domainدامنهٔ خرابیبزرگ‌ترین دسته‌ای که می‌تواند یک‌جا از کار بیفتد.The largest set of things that can fail together as one.
  • failure drillتمرین خرابیتمرین عمدی خرابی، پیش از شبی که واقعاً پیش می‌آید.Rehearsing a failure on purpose, before the night it happens for real.
  • fan-outپخش انشعابیپخش کردن یک کار یا یک رویداد به چند مقصد، یا موقع نوشتن یا موقع خواندن.Spreading one event or request across many destinations, at write time or at read time.
  • health checkبررسی سلامتپرسشی کوچک و تکراری که می‌گوید این نسخه می‌تواند ترافیک بگیرد یا نه.A small repeated question that decides whether this instance may take traffic.
  • latencyتأخیرمدت زمان رفت‌وبرگشت یک پیام؛ همان چیزی که کاربر منتظرش می‌ماند.The time a message takes to go and come back — what the user actually waits for.
  • load balancerتوزیع‌کنندهٔ بارسرویسی که درخواست‌ها را بین چند نسخهٔ سالم پخش می‌کند تا هیچ‌کدام تنها نماند.A service that spreads requests across healthy copies so no single one takes everything.
  • maintainabilityنگهداشت‌پذیریهزینهٔ نگهداشتن و تغییر دادن سیستم در طول سال‌ها.The cost of keeping a system alive and changing it over the years.
  • observabilityمشاهده‌پذیریتوانِ جواب دادن به سؤال‌های تازه، از روی چیزی که سیستم خودش بیرون می‌دهد.The ability to answer new questions from what the system already emits.
  • operabilityبهره‌برداری‌پذیریراحتیِ راه‌انداختن و سرپا نگه داشتن سیستم، برای آدم‌هایی که با آن کار می‌کنند.How easy it is to run and keep alive, for the people who actually do it.
  • percentileصدکعددی که می‌گوید چند درصد نمونه‌ها از آن کمترند؛ راه دیدن دنبالهٔ کند.A number saying what share of samples fall below it — the way to see the slow tail.
  • regionمنطقهیک محدودهٔ جغرافیایی که چند مرکز داده در آن جا می‌گیرد و با بقیه فاصله دارد.A geographic area holding several data centres, far from the others.
  • reliabilityقابلیت اطمینانکار کردن درستِ سیستم در طول زمان، حتی وقتی قطعه‌ای خراب می‌شود.The system doing its job correctly over time, even when a component goes wrong.
  • response timeزمان پاسخکل مدتی که کاربر منتظر می‌ماند، شامل انتظار در صف و برگشت پاسخ.The whole time the user waits, including queueing and the trip back.
  • rolling upgradeارتقای تدریجیعوض کردن نسخه‌ها یکی‌یکی، طوری که سرویس در تمام مدت جواب بدهد.Replacing copies one at a time so the service keeps answering throughout.
  • scalabilityمقیاس‌پذیریتوانایی سیستم برای جواب دادن به بار بیشتر، بدون اینکه سرعت یا کیفیت جواب خراب شود.A system's ability to keep serving well as the load on it grows.
  • SLAتوافق سطح خدمتقراردادی با مشتری که می‌گوید سرویس چقدر در دسترس و سریع باشد و اگر نبود چه می‌شود.A contract fixing how available and how fast the service must be, and what breaking it costs.
  • SLIشاخص سطح خدمتیک عدد اندازه‌گیری‌شده که می‌گوید سرویس چقدر خوب کار می‌کند.A measured number that says how well the service is doing.
  • SLOهدف سطح سرویسهدفی که تیم برای کیفیت سرویس می‌گذارد و با آن تصمیم می‌گیرد چه چیزی را قربانی کند.The target a team sets for its own service quality, and the line it uses to decide what to sacrifice.
  • SPOFتک‌نقطهٔ خرابیقطعه‌ای که خرابی‌اش کل سیستم را می‌خواباند، هرقدر بقیه سالم باشند.A part whose failure takes the whole system down, however healthy everything else is.
  • statelessبی‌حالتبین دو درخواست چیزی از تو نگه نمی‌دارد؛ هر نسخه هر درخواست را جواب می‌دهد.It keeps nothing about you between requests, so any instance can answer.
  • tail latencyتأخیر دنبالهکندترین بخش توزیع تأخیر، همان چیزی که کاربر واقعاً به یاد می‌آورد.The slow end of the latency distribution, the part a user actually remembers.
  • tail latency amplificationتقویت تأخیر دنبالهوقتی یک درخواست به چند سرویس وابسته است، احتمال برخورد با کندترین‌شان با تعدادشان بالا می‌رود.When one request depends on many services, the chance of hitting a slow one rises with their number.
  • throughputگذردهیتعداد کارهایی که یک سیستم در یک واحد زمان تمام می‌کند.How many jobs a system finishes in a unit of time.
  • working setمجموعهٔ کاریآن بخش از داده که در یک بازهٔ زمانی واقعاً استفاده می‌شود و باید در حافظه بماند.The slice of data actually used within a window of time, the slice that has to stay in memory.

۳3مدل‌های داده و زبان‌های کوئریData models and query languages

  • cardinalityکاردینالیتیتعداد چیزهایی که می‌توانند در دو طرف یک رابطه بنشینند.The number of things that can sit on each side of a relationship.
  • CQRSتفکیک خواندن و نوشتنجدا کردن مسیر نوشتن از مسیر خواندن تا هر کدام برای کار خودش ساخته شود.Separating the write path from the read path so each is shaped for its own job.
  • DataFrameدیتافریمجدولی که فقط می‌گویی چه می‌خواهی و حساب‌وکتاب کردن را به خودش می‌سپاری.A table you address by intent, and the computing is somebody else's problem.
  • declarativeاعلانیسبکی که فقط نتیجه را توصیف می‌کنی و ترتیب کارها را به سیستم می‌سپاری.A style where you describe the result and leave the steps to the system.
  • denormalizationنرمال‌زداییعمداً یک واقعیت را در چند جا نگه داشتن تا خواندن ارزان شود.Deliberately keeping one fact in several places so that reads get cheap.
  • document modelمدل سندینگه داشتن داده به شکل سندهای خودبسنده که با یک خواندن کامل می‌آیند.Storing data as self-contained documents that arrive whole in a single read.
  • event sourcingرویدادمحورینگه داشتن زنجیرهٔ رویدادها به‌جای وضعیت، و ساختن وضعیت از روی همان زنجیره.Keeping the chain of events instead of the state, and building the state from that chain.
  • graph modelمدل گرافینگه داشتن داده به شکل نقطه‌ها و یال‌ها، برای پرسش‌هایی که دنبال مسیر می‌گردند.Storing data as vertices and edges, for questions that hunt for a path.
  • impedance mismatchناهم‌خوانی امپدانسشکافی که وقتی داده در برنامه شیء است و در دیتابیس ردیف، سر باز می‌کند.The gap between data shaped as objects in code and as rows in a database.
  • keyset paginationصفحه‌بندی کلیدمحورصفحهٔ بعد را با «بعد از این رکورد» می‌گیری، نه با شمردن رکوردهای قبلی.Fetching the next page by naming the last row you saw, not by counting what came before.
  • localityمحلی‌بودننگه‌داشتن داده‌هایی که با هم خوانده می‌شوند، کنار هم روی دیسک.Storing data that is read together close together on disk.
  • materialized viewنمای مادی‌شدهذخیره کردن نتیجهٔ یک پرسش به شکل داده، تا هر بار از نو حساب نشود.Storing the result of a query as data so it is not computed from scratch every time.
  • N+1 queryکوئری N+1یک کوئری برای فهرست، بعد یکی برای هر ردیف؛ هزینه‌اش با تعداد ردیف‌ها جمع می‌شود.One query for the list, then one more for each row, so the bill grows with the rows.
  • normalizationنرمال‌سازیمرتب کردن داده طوری که هر واقعیت فقط یک بار نوشته شود.Organising data so that each fact is written down exactly once.
  • ORMنگاشت شیء-رابطهکتابخانه‌ای که ردیف‌های جدول را به شیءهای کد تبدیل می‌کند و کوئری را خودش می‌سازد.A library that turns table rows into objects for your code and writes the queries for you.
  • projectionبرون‌فکنیساختن یک نمای قابل پرسش از زنجیرهٔ رویدادها با یک تابع معین.Building a queryable view out of the event stream with one defined function.
  • query optimizerبهینه‌ساز کوئریبخشی که از یک کوئری چند نقشه می‌سازد و ارزان‌ترین را انتخاب می‌کند.The part that turns one query into several possible plans and picks the cheapest.
  • relational modelمدل رابطه‌اینگه داشتن داده در جدول‌های سطر و ستون، با رابطه‌هایی که با مقدار ساخته می‌شوند.Storing data in tables of rows and columns, with relationships made by matching values.
  • schema-on-readطرح‌واره هنگام خواندنتفسیر کردن شکل داده در لحظهٔ خواندن، به‌جای اجبار آن در لحظهٔ نوشتن.Interpreting the shape of the data at read time instead of enforcing it at write time.
  • star schemaطرح ستاره‌ایجدول مرکزی رویدادها، و چند جدول کوچک که جزئیات هر رویداد را توضیح می‌دهند.A central table of events, ringed by small tables that describe them.

۴4ذخیره‌سازی و بازیابیStorage and retrieval

  • ANN searchجست‌وجوی تقریبی نزدیک‌ترینپیدا کردن نزدیک‌ترین بردار با گشتن در بخشی از داده، نه همهٔ آن.Finding the nearest vector by searching part of the data instead of all of it.
  • B-treeدرخت Bساختار ایندکسی از صفحه‌های مرتب و شاخه‌بندی‌شده که با چند پرش به رکورد می‌رسد.An index built from sorted pages in a branching structure that reaches a record in a few hops.
  • Bloom filterفیلتر بلومساختاری کوچک که می‌گوید «قطعاً نیست» یا «شاید هست».A tiny structure that answers definitely not or maybe.
  • columnar storageذخیره‌سازی ستونیکنار هم گذاشتن مقادیر یک ستون روی دیسک، به‌جای کنار هم گذاشتن ردیف‌ها.Storing one column's values together on disk instead of storing whole rows together.
  • compactionفشرده‌سازیجمع کردن فایل‌های کوچک در فایل‌های بزرگ‌تر و دور ریختن نسخه‌های مرده.Merging small files into larger ones and throwing the dead versions away.
  • compressionفشرده‌سازی دادهکد کردن داده در بایت‌های کمتر، به بهای کار پردازنده در هر خواندن و نوشتن.Encoding data in fewer bytes, paid for with processor work on every read and write.
  • crash recoveryبازیابی پس از خرابیکارهایی که یک سیستم پس از خرابی ناگهانی انجام می‌دهد تا به حالت درست برگردد.The work a system does after a sudden failure to get back to a correct state.
  • durabilityدوامتضمین اینکه دادهٔ تأییدشده بعد از خرابی هم سر جایش باشد.The guarantee that acknowledged data is still there after a crash.
  • fsyncهمگام‌سازی با دیسکوادار کردن سیستم‌عامل به نشاندن داده روی رسانه، پیش از برگشتن.Forcing the operating system to put the data on the medium before returning.
  • group commitکامیت گروهیجمع کردن چند کامیت در یک fsync تا هزینهٔ دیسک بین همه تقسیم شود.Batching several commits into one fsync so the disk cost is shared.
  • hash indexایندکس هشیایندکسی که با محاسبهٔ هش، محل کلید را در یک حرکت پیدا می‌کند.An index that computes a key's location in one step instead of walking a tree.
  • in-memory databaseپایگاه دادهٔ درون‌حافظه‌ایپایگاه داده‌ای که نسخهٔ اصلی داده در حافظه است، نه روی دیسک.A database whose authoritative copy of the data lives in memory, not on disk.
  • indexایندکسساختاری کنار داده که پیدا کردن رکورد را از گشتن در همه‌چیز نجات می‌دهد.A structure beside the data that saves you from scanning everything to find one record.
  • inverted indexایندکس معکوسنگاشتی از هر واژه به فهرست سندهایی که آن واژه را دارند.A map from each word to the list of documents that contain it.
  • LSM-treeدرخت LSMدرختی که نوشتن را در حافظه جمع می‌کند و مرتب روی دیسک می‌ریزد.A tree that buffers writes in memory and flushes them to disk in order.
  • memtableجدول حافظه‌اینگاشت مرتبی در حافظه که نوشتن‌های تازه را تا لحظهٔ ریختن روی دیسک نگه می‌دارد.A sorted map in memory that holds fresh writes until they are flushed to disk.
  • page splitشکستن صفحهوقتی صفحهٔ درخت پر است، به دو نیم می‌شود و کلید میانی به سطح بالاتر می‌رود.When a tree page is full it becomes two, and the middle key moves up a level.
  • recallبازخوانیسهم نتایج درست و واقعی که سیستم توانست پیدا کند.The share of the genuinely correct results the system managed to find.
  • SSTableجدول رشته‌ای مرتبفایل مرتب و تغییرناپذیر کلید-مقدار روی دیسک که فقط یک بار نوشته می‌شود.A sorted, immutable key-value file on disk that is written exactly once.
  • top-Kکی نتایج برترپیدا کردن K نتیجهٔ برتر، بدون مرتب کردن کل مجموعه.Finding the K best results without sorting the whole collection.
  • trigram indexایندکس سه‌حرفیایندکسی از هر سه حرف پشت سر هم، برای پیدا کردن زیررشته و الگو.An index of every three consecutive characters, built to find substrings and patterns.
  • vector indexایندکس برداریساختاری که نزدیک‌ترین بردارها به یک پرس‌وجو را بدون گشتن در همه پیدا می‌کند.A structure that finds the vectors nearest a query without visiting all of them.
  • WALلاگ پیش‌نوشتدفتری که پیش از هر تغییر، قصدِ انجامش را روی دیسک می‌نویسد تا خرابی چیزی را گم نکند.A log that records the intent of every change on disk before it happens, so a crash loses nothing.
  • write amplificationتقویت نوشتننسبت بایت‌هایی که رسانه واقعاً می‌نویسد به بایتی که برنامه نوشته است.The ratio of bytes the medium actually writes to bytes the application wrote.

۵5کدگذاری و تکاملEncoding and evolution

  • Avroآوروقالبی دودویی که اسکیمای نویسنده را همراه داده می‌برد و خواننده با اسکیمای خودش تطبیقش می‌دهد.A binary format that carries the writer's schema with the data and resolves it against the reader's.
  • backward compatibilityسازگاری با گذشتهکد تازه، داده و پیام‌های قدیمی را می‌خواند، پس می‌توانی نسخه را بالا ببری.New code can read data and messages written by the old code, so a version upgrade stays safe.
  • Base64بیس ۶۴تبدیل بایت‌های دودویی به نویسه‌های متنی، تا از مجرای متنی رد شوند.Turning binary bytes into text characters so a text-only channel can carry them.
  • durable executionاجرای پایداراجرای گردش‌کاری که هر قدمش ذخیره می‌شود، تا بعد از خرابی از همان‌جا ادامه دهد.Running a workflow whose every step is recorded, so a crash resumes from the last finished step.
  • encodingکدگذاریتبدیل داده به قالبی از بایت که طرف مقابل دوباره از آن داده بسازد.Turning data into a byte layout that the other side can turn back into data.
  • field tagبرچسب فیلدشماره‌ای ثابت که هر فیلد را روی سیم مشخص می‌کند، نه اسمش.A fixed number that identifies each field on the wire, not its name.
  • idempotency keyکلید تکرارناپذیریشناسه‌ای که کلاینت همراه درخواست می‌فرستد تا سرور تکرار را بشناسد و یک بار اثر کند.An id the client sends with a request so the server can spot a retry and act once.
  • Protocol Buffersبافرهای پروتکلقالبی دودویی که فیلد‌ها را با شماره می‌شناسد و کدش را از یک فایل قرارداد می‌سازد.A binary format that identifies fields by number and generates code from a contract file.
  • RESTرستسبکی که هر چیز را یک منبع با آدرس می‌بیند و با خودِ HTTP حرف می‌زند.A style that treats everything as an addressable resource and talks through HTTP itself.
  • RPCفراخوانی از راه دورصدا زدن کدی روی ماشین دیگر، طوری که شبیه صدا زدن تابع خودی به نظر برسد.Calling code on another machine in a way that looks like calling your own function.
  • schemaاسکیماتعریف نام و نوع و قید هر تکه از داده، یک بار و برای همه.A one-time definition of every field's name, type and constraints, shared by everyone.
  • schema evolutionتحول اسکیماعوض کردن قالب داده بدون شکستن کد‌ها و داده‌ای که از قبل هست.Changing the data format without breaking the code or the data already stored.
  • schema registryثبت اسکیماانبار مرکزی نسخه‌های اسکیما که پیش از پذیرفتن تغییر، سازگاری را می‌سنجد.A central store of schema versions that checks compatibility before accepting a change.
  • serializationسریال‌سازیتبدیل یک ساختار در حافظه به دنباله‌ای از بایت، و برگرداندن دوباره‌اش.Turning an in-memory structure into a stream of bytes, and back again.
  • service meshشبکهٔ سرویسیک پروکسی کنار هر سرویس که کار‌های شبکه را از کد بیرون می‌کشد.A proxy beside every service that takes the network chores out of your code.
  • varintعدد متغیرطولعددی که به اندازهٔ بزرگی خودش جا می‌گیرد، نه به اندازهٔ ظرف ثابتش.A number that takes as many bytes as it needs, not as many as its type allows.

۶6تکثیر (Replication)Replication

  • anti-entropyضدآنتروپیفرایند پس‌زمینه‌ای که نسخه‌ها را مقایسه می‌کند و اختلاف‌هایی را که از مسیر عادی جا مانده‌اند می‌بندد.A background process that compares copies and closes the gaps the normal path left behind.
  • conflict resolutionحل تعارضقاعده‌ای است که وقتی دو نوشتن هم‌زمان یک چیز را عوض می‌کنند، تکلیف مقدار نهایی را روشن می‌کند.The rule that decides what the value becomes when two writes change the same thing at once.
  • consistencyسازگاریقراردادی که می‌گوید وقتی داده چند نسخه دارد، خواندن‌ها چه چیزی را مجازند ببینند.The contract about which version of the data a read may see when copies differ.
  • CRDTنوع دادهٔ مقاوم به تعارضنوع داده‌ای که هر دو نسخه‌اش را می‌شود به هر ترتیبی جمع کرد و نتیجه همیشه یکی است.A data type whose copies can be combined in any order and always land on the same result.
  • eventual consistencyسازگاری نهاییاگر نوشتن تازه‌ای نرسد، همهٔ نسخه‌ها بالاخره به یک مقدار می‌رسند، بی‌آنکه کسی بگوید کِی.If no new writes arrive, every copy ends up with the same value, with no promise about when.
  • hinted handoffتحویل با یادداشتوقتی همانند مقصد غایب است، نود دیگری نوشتن را با یک یادداشت نگه می‌دارد.When a write's home replica is away, another node holds it with a note and delivers it later.
  • last write winsآخرین نوشتن برندهوقتی دو نوشتن به یک کلید می‌رسند، آن‌که زمان بزرگ‌تری دارد می‌ماند و بقیه دور ریخته می‌شوند.When two writes hit one key, the one with the larger timestamp survives and the others are discarded.
  • leaderرهبرنودی که نوشتن‌ها را می‌پذیرد و ترتیبشان را تعیین می‌کند، و بقیه همان ترتیب را دنبال می‌کنند.The node that accepts writes and fixes their order, while the rest follow that order.
  • leaderless replicationتکثیر بی‌رهبرهمهٔ نسخه‌ها نوشتن را می‌پذیرند و نوشتن وقتی موفق است که تعداد کافی از آن‌ها جواب بدهند.Every replica accepts writes; the write succeeds once enough of them answer.
  • membershipعضویت خوشهفهرست نودهایی که رسماً بخشی از خوشه‌اند و تصمیم‌ها بر اساس آن‌ها گرفته می‌شود.The list of nodes officially inside the cluster, the list every decision is counted against.
  • monotonic readsخواندن یکنوااگر یک بار نسخهٔ تازه را دیدی، دیگر نسخهٔ قدیمی‌تر را نمی‌بینی.Once you have seen a newer version, you will never be shown an older one.
  • multi-leader replicationتکثیر چندرهبرچند رهبر، هر کدام در یک جا، که نوشتن‌های محلی را می‌پذیرند و به هم می‌فرستند.Several leaders, each in one place, accepting local writes and shipping them to each other.
  • read repairترمیم در خواندنهنگام خواندن، نسخه‌های مختلف را مقایسه می‌کند، تازه‌ترین را برمی‌گرداند و بقیه را با آن اصلاح می‌کند.On a read it compares the copies, returns the newest, and fixes the others with it.
  • read-your-writesخواندن نوشته‌های خودهر خواندنی که بعد از نوشتن خودت می‌آید، باید دست‌کم همان نوشتن را ببیند.Any read after your own write must see at least that write.
  • replicaهمانندیک کپی کامل از داده، روی ماشینی دیگر، که همان داده را نگه می‌دارد.A complete copy of the data on another machine, holding the same data.
  • replicationتکثیرنگه‌داشتن چند نسخه از همان داده روی ماشین‌های جدا، تا خرابی یک ماشین داده را نبرد.Keeping several copies of the same data on separate machines so one failure does not take it away.
  • replication lagتأخیر تکثیرفاصلهٔ زمانی بین نوشتن روی نسخهٔ اصلی و دیده شدنش روی نسخه‌های دیگر.The delay between a write on the primary and its visibility on the other copies.
  • single-leader replicationتکثیر تک‌رهبرالگویی که در آن یک نود همهٔ نوشتن‌ها را می‌پذیرد و بقیه همان ترتیب را دنبال می‌کنند.A pattern where one node accepts every write and the others follow the same order.
  • split brainمغز دو نیمهوقتی دو بخش از خوشه هر کدام خودشان را رهبر می‌دانند و هر دو می‌نویسند.When two parts of a cluster each believe they lead, and both keep accepting writes.
  • stale dataدادهٔ کهنهنسخه‌ای از داده که زمانی درست بود و از منبع عقب افتاده است.A copy of the data that was once correct and has fallen behind its source.
  • sticky sessionنشست چسبندهمتعادل‌کنندهٔ بار همهٔ درخواست‌های یک نشست را به یک بک‌اند می‌فرستد.A load balancer sends every request of one session to the same backend.
  • synchronous replicationتکثیر همگامتکثیری که در آن رهبر پیش از پاسخ دادن، تأیید همانند را می‌خواهد.Replication in which the leader waits for a follower's acknowledgement before answering.
  • vector clockساعت برداریشمارنده‌های هر نود را کنار هم می‌گذارد تا ترتیب علّی رویدادها را بفهمد.It stacks each node's counter together to work out the causal order of events.
  • version vectorبردار نسخهشمارندهٔ هر همانند را روی خود مقدار می‌گذارد تا هم‌زمانی را ببیند.It carries one counter per replica on the value itself, so concurrency becomes visible.

۷7تقسیم (Sharding)Sharding

  • consistent hashingهش سازگارنگاشت گره‌ها و کلیدها روی یک حلقه، تا افزودن گره فقط همسایه‌اش را جابه‌جا کند.Mapping nodes and keys onto one ring so a joining node only takes over its neighbour's slice.
  • coordinatorهماهنگ‌کنندهگرهی که درخواست را می‌گیرد، به شاردهای درست می‌فرستد و یک جواب برمی‌گرداند.The node that takes a request, sends it to the right shards and returns one answer.
  • cutoverبرش انتقاللحظهٔ سوییچ از سیستم قدیم به نو، با همهٔ نوشتن‌های نیمه‌کاره.The moment you switch from the old system to the new, with every write still in flight.
  • gossip protocolپروتکل شایعههر گره دوره‌ای چند گره دیگر را صدا می‌زند و خبر خودش پخش می‌شود.Every node calls a few others on a timer, and the news spreads itself.
  • hash shardingتقسیم هشیتقسیم کلیدها با یک تابع هش، تا بار یکنواخت پخش شود و ترتیب قربانی شود.Placing keys by a hash so the load spreads evenly and ordering is what you give up.
  • hot spotنقطهٔ داغبخشی از داده که بیشتر از سهمش درخواست می‌گیرد و بقیه بیکار می‌مانند.A slice of the data that takes more requests than its share while the rest sits idle.
  • key-range shardingتقسیم بازه‌ایبریدن کلیدها به بازه‌های پیوسته، تا پیمایش یک بازه در یک شارد تمام شود.Cutting keys into contiguous ranges so a range scan finishes inside one shard.
  • partition keyکلید تقسیمستونی که جای هر رکورد را تعیین می‌کند و می‌گوید کدام پرس‌وجو یک‌جا جواب می‌گیرد.The column that decides where each record lives, and which queries can be answered in one place.
  • rebalancingبازتوازنجابه‌جا کردن داده و بار بین گره‌ها، وقتی ظرفیت یا خود گره‌ها عوض می‌شوند.Moving data and load between nodes when capacity changes or the nodes themselves change.
  • request routingمسیریابی درخواسترساندن هر درخواست به گره یا شارد صاحب کلید، بی‌آنکه کلاینت همه را بگردد.Getting each request to the node that owns its key, without the client searching everywhere.
  • secondary indexایندکس ثانویهفهرست دومی روی ستونی جز کلید، که راه رسیدن به رکورد را کوتاه می‌کند.A second listing on a column other than the key, so you do not have to search everything.
  • service discoveryکشف سرویسراهی که یک سرویس، آدرس نمونه‌های سالم سرویس دیگر را پیدا کند.A way for one service to find the addresses of another's healthy instances.
  • shardingشاردینگشکستن داده به تیکه‌های جدا که هر رکورد فقط توی یک تیکه می‌نشیند.Splitting data into disjoint pieces so each record lives in exactly one piece.
  • skewکجی بارناهمواری حجم یا بار بین بخش‌ها؛ میانگین پنهانش می‌کند، بیشترین مقدار لو می‌دهد.Uneven size or load across the pieces; the average hides it, the maximum gives it away.
  • virtual nodeگرهٔ مجازیهر سرور چند نقطهٔ کوچک روی حلقه دارد، نه یک نقطهٔ بزرگ.Each server holds several small points on the ring instead of one big one.

۸8تراکنش‌ها (Transactions)Transactions

  • ACIDایسیدچهار قولِ جدا دربارهٔ یک تراکنش: همه‌یاهیچ، قانون‌های خودت، جدایی از هم‌زمانی، و ماندن بعد از تأیید.Four separate promises about one transaction: all-or-nothing, your own rules, no interference, and survival after the answer.
  • atomicityاتمی‌بودنیا همهٔ نوشتن‌های یک تراکنش می‌مانند، یا هیچ‌کدام؛ حالت وسط وجود ندارد.Either every write of a transaction stays or none of them does. There is no middle state.
  • commitکامیتلحظه‌ای که تصمیم تراکنش پایدار می‌شود و بعد از آن فقط اجرا می‌شود، نه عوض.The instant the transaction's decision becomes durable; afterwards it is carried out, not changed.
  • compare-and-setمقایسه و جایگذارینوشتنی که فقط وقتی انجام می‌شود که مقدار فعلی همان مقدارِ مورد انتظار باشد.A write that happens only when the current value still equals the value you expected.
  • contentionرقابت بر منابعوقتی چند کار هم‌زمان سر یک منبع صف می‌کشند و سرعت کل می‌افتد.When several jobs queue for one resource and the whole system slows down.
  • deadlockبن‌بستدو تراکنش که هر کدام قفلِ دیگری را می‌خواهد و هر دو تا ابد منتظر می‌مانند.Two transactions each holding a lock the other needs, both waiting forever.
  • dirty readخواندن کثیفخواندنِ نوشته‌ای که هنوز کامیت نشده و ممکن است همین حالا برگردد.Reading a write that has not committed yet and may still vanish.
  • dirty writeنوشتن کثیفنوشتنی که روی نوشتنِ کامیت‌نشدهٔ دیگری می‌افتد و راه بازگشت را می‌بندد.A write that lands on another transaction's uncommitted write and closes the door on rollback.
  • distributed transactionتراکنش توزیع‌شدهتراکنشی که چند سیستم جدا را در یک «همه یا هیچ» شریک می‌کند.A transaction that makes several separate systems share one all-or-nothing decision.
  • exclusion constraintقید طردقاعده‌ای که می‌گوید هیچ دو ردیفی نباید در یک بازه با هم هم‌پوشانی داشته باشند.A rule saying no two rows may overlap on the same range.
  • in-doubt transactionتراکنش در ابهامتراکنشی که همه رأی داده‌اند ولی هیچ‌کس نمی‌داند کامیت شده یا نه.A transaction where everyone voted yes and nobody knows whether it committed.
  • isolation levelسطح ایزولاسیونقراردادی که می‌گوید کدام ناهنجاری‌های هم‌زمانی مجازند و کدام ممنوع.A contract that says which concurrency anomalies are allowed and which are forbidden.
  • lost updateبه‌روزرسانی گم‌شدهخواندن-تغییر-نوشتنِ هم‌زمان که یکی نوشتن دیگری را می‌بلعد.Two concurrent read-modify-write cycles, where one silently swallows the other.
  • materializing conflictsمادی‌سازی تعارض‌هایک چیز واقعی می‌سازی تا چیزی که هنوز نیست هم بشود قفلش کرد.You build a real thing so that something that does not exist yet can be locked too.
  • MVCCکنترل هم‌زمانی چندنسخه‌اینگه داشتن چند نسخه از هر ردیف تا خواندن از یک عکس ثابت کار کند.Keeping several versions of each row so reads work from a fixed picture.
  • optimistic concurrency controlکنترل همزمانی خوش‌بینانهبی‌قفل کار می‌کنی و فقط آخرش می‌فهمی کسی داده را عوض کرده یا نه.You work without locks and only find out at the end whether someone changed the data.
  • phantom readخواندن شبحنوشتنِ تراکنش دیگر، نتیجهٔ جست‌وجوی تو را عوض می‌کند.Another transaction's write changes the result of your search.
  • predicate lockقفل گزاره‌ایقفلی که روی شرط می‌نشیند، نه روی ردیف‌هایی که الان وجود دارند.A lock that sits on the condition, not on the rows that happen to exist now.
  • read committedخواندن کامیت‌شدهفقط چیزهایی را می‌بینی که نهایی شده‌اند، ولی هر بار ممکن است دنیای تازه‌ای ببینی.You only see what is final, but each look may show you a different world.
  • read skewکجی خواندنخواندن چند چیز در چند لحظه، طوری که با هم جور درنیایند.Reading several things at different moments so that they no longer add up.
  • repeatable readخواندن تکرارپذیرقول اینکه هر چه در یک تراکنش خواندی، تا آخر همان بماند.The promise that whatever you read inside a transaction stays that way until it ends.
  • serializabilityسریال‌پذیریتضمین اینکه نتیجهٔ اجرای هم‌زمان با یک ترتیب سریال از همان تراکنش‌ها جور است.The guarantee that a concurrent result matches some serial order of the same transactions.
  • SKIP LOCKEDرد کردن قفل‌شده‌هابرداشتن کاری که هنوز دست کسی نیست و رد کردن بقیه، به‌جای ایستادن در صف.Take the next job nobody is already holding, and step over the rest instead of queueing.
  • snapshot isolationجداسازی اسنپ‌شاتهر تراکنش دنیا را همان‌طور می‌بیند که در لحظهٔ شروعش بود.Every transaction sees the database as it was at the instant it started.
  • SSIجداسازی اسنپ‌شات سریالیهمان جداسازی اسنپ‌شات، به‌اضافهٔ نگهبانی که در لحظهٔ کامیت تعارض را می‌بیند و یکی را برمی‌گرداند.Snapshot isolation plus a commit-time guard that spots an unserializable outcome and sends one transaction back.
  • stored procedureرویهٔ ذخیره‌شدهکدی که داخل خود پایگاه داده می‌نشیند و با یک صدا زدن اجرا می‌شود.Code that lives inside the database itself and runs when you call its name.
  • two-phase commitکامیت دومرحله‌ایاول همه آماده می‌شوند، بعد همه با هم کامیت می‌کنند؛ هیچ‌کس تنها تصمیم نمی‌گیرد.Everyone prepares first, then everyone commits together; nobody decides alone.
  • two-phase lockingقفل‌گذاری دومرحله‌ایقفل گرفتن پشت‌سرهم و آزاد نکردن هیچ قفلی تا پایان کار.Acquire locks one after another and release none of them until the work is done.
  • write skewانحراف نوشتندو تراکنش چیزهای جدا می‌نویسند، ولی هر کدام بر اساس چیزی تصمیم گرفته که آن یکی عوضش کرده.Two transactions write different rows, each having decided on the basis of what the other changed.
  • XAاکس‌اییک قرارداد مشترک که چند سیستم جدا را زیر یک تراکنش جمع می‌کند.A shared contract that lets separate systems stand under one transaction.

۹9دردسرهای سیستم‌های توزیع‌شدهThe Trouble with Distributed Systems

  • Byzantine faultخرابی بیزانسیخرابی‌ای که در آن یک گره هر پیامی، از جمله پیام دروغ و متناقض، می‌فرستد.A failure where a node may send any message at all, including lies and contradictions.
  • clock skewانحراف ساعتفاصلهٔ میان ساعت‌های چند ماشین در یک لحظه، که کمکم بزرگ‌تر هم می‌شود.The gap between several machines' clocks at the same instant, which keeps growing.
  • exponential backoffعقب‌نشینی نماییبعد از هر خطا فاصلهٔ تلاش بعدی را بیشتر کن تا سیستمِ در فشار را بیشتر نکوبی.After each failure, wait longer before the next try, so a system already under pressure is not hit harder.
  • failure detectorآشکارساز خرابیراهی برای حدس زدن اینکه یک ماشین هنوز کار می‌کند یا از کار افتاده.A way of guessing whether another machine is still working or has stopped.
  • fencing tokenتوکن حصارشمارهٔ صعودی که با هر اجاره صادر می‌شود تا منبع، نوشتن صاحب قدیمی را رد کند.A rising number issued with each lease, so the resource can reject the old owner's writes.
  • idempotencyتکرارناپذیریکاری که انجام دادنش دو بار، همان نتیجهٔ یک بار را می‌دهد.Work whose second run leaves the world exactly as the first did.
  • invariantنابردارجمله‌ای دربارهٔ داده که در هر وضعیت درست است و نباید لحظه‌ای بشکند.A statement about the data that holds in every state and must never break.
  • jitterلرزشکمی تصادف در زمان‌بندی، تا تلاش‌ها و درخواست‌ها روی هم نیفتند.A little randomness in timing so retries and requests stop landing together.
  • leaseاجاره‌نامهقفلی که تاریخ انقضا دارد، تا یک گرهٔ مرده قفل را برای همیشه نگه ندارد.A lock with an expiry, so a dead holder cannot keep it forever.
  • livenessزنده‌مانیقولی که می‌گوید سیستم بالأخره کاری را انجام می‌دهد، نه فقط خراب نمی‌شود.The promise that the system eventually gets something done, not merely that it never breaks.
  • monotonic clockساعت یکنواساعتی که فقط جلو می‌رود و برای اندازه گرفتن فاصله ساخته شده، نه برای تاریخ.A clock that only moves forward, built to measure how long something took, not when.
  • network partitionتقسیم شبکهوقتی شبکه دو گروه از گره‌ها را جدا می‌کند، هرچند هر دو گروه سالم کار می‌کنند.When the network cuts one group of nodes off from another, though both groups are up.
  • NTPپروتکل زمان شبکهپروتکلی که ساعت کامپیوتر را با یک ساعت مرجع، از راه شبکه، هم‌تراز می‌کند.A protocol that aligns a computer's clock with a reference clock over the network.
  • partial failureخرابی جزئیخرابی‌ای که فقط بخشی از سیستم را می‌گیرد و بقیه را سالم می‌گذارد.A failure that takes down part of the system and leaves the rest running.
  • process pauseتوقف فرآیندبازه‌ای که کد تو اجرا نمی‌شود، هرچند فرآیند مرده نیست.A stretch of time when your code does not run at all, though the process is not dead.
  • retryبازتلاشفرستادن دوبارهٔ همان درخواست، به این امید که بار اول کامل انجام نشده باشد.Sending the same request again, in the hope that the first attempt did not fully happen.
  • safetyایمنیخاصیتی که می‌گوید در هیچ لحظه‌ای چیز بدی رخ نمی‌دهد، حتی یک بار.A property saying that at no moment does something bad happen, not even once.
  • system modelمدل سیستمفهرست صریح چیزهایی که ممکن است خراب شود، تا معلوم شود الگوریتم چه چیزی را تضمین می‌کند.An explicit list of what may go wrong, so it is clear what an algorithm actually promises.
  • timeoutمهلتمدتی که برای یک پاسخ صبر می‌کنی و بعد تصمیم می‌گیری، چون انتظار بیشتر چیزی یادت نمی‌دهد.How long you wait for an answer before deciding, because waiting longer teaches you nothing.
  • unknown outcomeنتیجهٔ نامشخصحالتی که درخواست رفته و هیچ‌کس نمی‌داند انجام شده است یا نه.The state where a request has gone out and nobody knows whether it took effect.
  • wall clockساعت دیواریساعتی که تاریخ و ساعت روز را می‌دهد، و می‌تواند بپرد یا عقب برود.A clock that gives the date and time of day, and can jump or run backwards.

۱۰10سازگاری و اجماعConsistency and Consensus

  • CAP theoremقضیهٔ CAPدر قطع شبکه، سیستم یا جواب می‌دهد یا درست می‌ماند؛ هر دو با هم ممکن نیست.During a partition a system either answers or stays correct, and it cannot do both.
  • consensusاجماعتوافقی که همه روی یک مقدار می‌کنند و بعد از آن، برگشت‌پذیر نیست.An agreement on one value that every node accepts and that never gets reopened.
  • coordination serviceسرویس هماهنگیسرویس کوچک و قابل‌اعتمادی که تصمیم‌های هماهنگی را نگه می‌دارد، نه دادهٔ اصلی را.A small, trusted service that holds coordination decisions, never your real data.
  • FLP impossibilityناامکانی FLPنتیجه‌ای که می‌گوید در شبکهٔ نامطمئنِ کاملاً ناهمزمان، اجماعِ هم‌زمان مطمئن و همیشه‌پاسخ ممکن نیست.The result that says deterministic consensus cannot be both safe and always terminating on an asynchronous network.
  • happens-beforeرخ‌دادن پیش ازترتیب جزئی رویدادها: یکی پیش از دیگری است اگر واقعاً می‌توانسته بر آن اثر بگذارد.A partial order of events: one precedes another only if it could have influenced it.
  • high-water markخط تراز بالاخطی که همه‌چیز زیرش قطعی است و بالای آن هنوز ممکن است عوض شود.The line below which everything is final and above which nothing is promised.
  • hybrid logical clockساعت منطقی ترکیبیترکیبی از زمانِ فیزیکی و شمارندهٔ منطقی که هم نزدیک به واقعیت است و هم ترتیبِ علّی را حفظ می‌کند.A physical timestamp plus a logical counter: close to real time and still causally ordered.
  • Lamport clockساعت لمپورتشمارنده‌ای که با هر رویداد یکی جلو می‌رود و با هر خبر، از خبر جلو می‌زند.A counter that ticks on every event and jumps past every message it receives.
  • leader electionانتخاب رهبرانتخاب یک گره به‌عنوان تصمیم‌گیرنده، طوری که هیچ‌وقت دو رهبر همزمان نباشند.Picking one node to decide, so that two leaders never exist at once.
  • linearizabilityخطی‌پذیریسیستم طوری رفتار می‌کند که انگار یک نسخه دارد و هر عملیات در یک لحظه اثر می‌گذارد.The system behaves like a single copy where every operation lands at one instant.
  • PACELCپاسلکتعمیمِ CAP: اگر پارتیشن باشد بین A و C، وگرنه بین L و C.CAP extended: under a partition choose A or C, otherwise choose L or C.
  • quorumکوئرومحداقل گره‌هایی که باید در خواندن یا نوشتن شرکت کنند تا نتیجه معتبر باشد.The fewest nodes that must take part in a read or write for the result to count.
  • state machine replicationتکثیر ماشین حالتهمهٔ نسخه‌ها یک دستور را به یک ترتیب اعمال می‌کنند و به یک وضعیت می‌رسند.Every copy applies the same commands in the same order and ends in one state.
  • strict serializabilityسریالی‌بودن اکیدسریالی‌بودن به‌علاوهٔ احترام به زمان واقعی: اگر A قبل از B تمام شد، B نمی‌تواند اول دیده شود.Serializability plus real-time order: if A finished before B began, B must not appear first.
  • timestamp oracleاوراکل زمانسرویسی که مهرهای زمانیِ یکنوا و بدون شکاف صادر می‌کند تا ترتیب جهانی قابل تعریف باشد.A service that issues monotonic, gapless timestamps so a global order can be defined.
  • total order broadcastپخش کل‌ترتیبهمهٔ گره‌ها همان پیام‌ها را به همان ترتیب تحویل می‌گیرند، بدون استثنا.Every node delivers the same messages in the same order, with no exceptions.
  • unique ID generatorتولید شناسهٔ یکتاساختنِ شناسه‌ای که در کل سیستم یکتاست، بدون اینکه هر نوشتن منتظر یک شمارنده بماند.Producing an identifier that is unique across the system without every write queueing on one counter.

  • append-only logلاگ فقط-افزودنیدفتری که فقط در انتهایش می‌نویسی و هیچ سطری را پاک نمی‌کنی.A ledger you only ever write to at the end, never erasing a line.
  • batch processingپردازش دسته‌ایخواندن یک‌جای داده‌ای که اندازه‌اش معلوم است و ساختن خروجی تازه از آن.Reading a data set of known size in one go and producing a fresh output from it.

  • immutable dataدادهٔ تغییرناپذیرداده‌ای که فقط اضافه می‌شود و نسخهٔ قبلی‌اش همیشه دست‌نخورده می‌ماند.Data that is only ever added to, while every earlier version stays untouched.
